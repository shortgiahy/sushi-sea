- Decisions: **Services stay `.server.lua` Scripts exactly as PRD §7.1 names them, but each Script is now a thin bootstrap that `require()`s a same-named `ServerStorage/Modules` ModuleScript holding the actual logic** — resolves a real tension the task brief flagged: PRD §7.1's literal filenames make `PlayerDataService.server.lua` a Script (Rojo: `.server.lua` → Script), but Scripts can't be `require()`d, so a Bootstrap-wires-services model and any future cross-service access to player data (M5's `EconomyService` will need to read/write gold; M9's `OfflineBankCalculator` will need snapshot fields) would be structurally impossible if all the logic lived only in the Script. Splitting logic into `ServerStorage/Modules/PlayerDataService.lua` fixes both problems at once and matches the reference `DataManager`/thin-`Script` pattern in the `dev-systems` persona doc, without deviating from a single PRD-specified filename or path · `PlayerDataService.lua` takes its DataStore as a constructor argument (`PlayerDataService.new(dataStore)`) instead of calling `DataStoreService:GetDataStore(...)` itself — this is what makes it possible to unit-test the full load/save/retry/migrate composition with a mock store, not just the leaf pure functions in isolation, and it costs nothing since only the Script ever constructs a real one · migration chain models "no `meta.schemaVersion` field / not a table at all" as version 0 rather than erroring or defaulting outright — this is the only way to give the chain mechanism a real, testable migration today (current schema is v1, so there's nothing else to migrate from yet), and it's also the realistic legacy case: any data saved before this module existed has no `schemaVersion` field · added a `taskLib = if task ~= nil then task else require("@lune/task")` shim inside `DataStoreRetry.lua` after discovering Lune does not expose `task` as a true global the way real Roblox does (confirmed by a throwaway script: `type(task)` is `"nil"` under `lune run`, `require("@lune/task")` is what actually works) — without it, `retryAsync`'s backoff wait would error every time under the headless test runner; the shim is a no-op in real Roblox since `task` is never nil there, so the `@lune/task` require string (which wouldn't resolve in Rojo/Studio) is never evaluated on that path · did not add `--!strict` to the new files — PRD §8 says "where possible," but there's no `luau-analyze` or equivalent in this toolchain to verify strict mode actually compiles clean before shipping it, and M1's own scaffold files shipped without it too;
